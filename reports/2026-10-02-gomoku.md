# Online Gomoku portfolio release

Deployed on 2026-10-02, with verification recorded on 2026-10-03 (Asia/Singapore), as production release `20261002T1556Z-gomoku`. The owner requested a game in the portfolio that friends could play together online. The game is available at [Play Gomoku](https://huangzhijun.online/play/gomoku), with entries on the homepage and `/work`.

## Scope

- A 15 × 15 board with a shareable room link, two player seats, server-validated alternating moves, win detection, resignation, and mutually agreed rematches that exchange colors.
- Same-tab refresh restores the board and player seat. A browser-generated 256-bit request identity is saved before creating or joining a room; retried requests recover the original room or seat after a lost response. The server stores identity hashes, and a unique creator identity prevents concurrent retries from creating multiple rooms.
- Same-device practice is explicitly labeled. Public room visitors may watch; a third visitor cannot take a player seat.
- The API uses existing Hono, Drizzle, and PostgreSQL. Migration `0009_gomoku_rooms` adds one independent table, a unique creator-identity constraint, and an expiry index. Rooms expire after 24 hours. No new dependency, permanent service, proxy configuration, or administrator permission was needed.
- Homepage project card and a playable invitation on `/work` point to the game.

## Verification

- Local API typecheck, security regression, PostgreSQL/HTTP game regression, and compilation passed. Game regressions cover rules, concurrent requests, lost-response recovery, seat identities, rematches, expiry, request body limits, and creation quotas. The existing publishing regression passed separately.
- Frontend lint, typecheck, and the Next.js production build passed, generating 70 pages and the game route. Sixteen key source files, including the component, client, service, schema, migration and portfolio entries, matched the final build snapshot byte for byte.
- Independent Windows and Linux SHA-256 checks agreed on both final packages. Package path inspection found no `.git`, environment files, private directory, or secrets directory.
- Public home, portfolio, game, notes, and other existing page requests returned HTTP 200. Existing content preservation was verified after adding the game card.
- The deployed public API passed 41 checks with two independent HTTP clients. They created and joined rooms, exchanged moves, reached five in a row, restored a seat and board after refresh, agreed on a rematch and swapped colors, resigned, and verified spectator and invalid-token restrictions. Concurrent joins allocated one seat; stale concurrent moves committed once; concurrent creation retries returned one room; a lost join response recovered the original seat without another write.

CUA and Browser Harness were unavailable during acceptance. Rendered browser UI, mobile layout, and actual touch interaction remain unverified. The independent HTTP clients verify the live multiplayer protocol and persistence, without establishing browser interaction acceptance.
