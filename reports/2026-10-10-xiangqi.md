# Blog-hosted Xiangqi

User request: add the existing invitation-based Chinese chess game to the personal blog, like Gomoku and Bubble Arena.

## Scope

- `/play/xiangqi/`: mobile canvas, raised wooden pieces, practice mode, same-device legacy mode, invitation links and return-to-blog link.
- `/api/xiangqi`: anonymous HttpOnly cookie, server-side identity hash, legal moves, PostgreSQL row-lock transactions, version and request replay checks. Opponent consent for undo, draw and rematch. Room access expires after 48 hours; no automatic physical purge yet.
- Add one independent `xiangqi_rooms` table and index. Existing game and content tables are untouched.
- Reuse the previous Xiangqi engine/domain/client. No external fonts, CDN, WebRTC relay, new dependency, account, or persistent process.

## Deployment isolation

Publish only new Xiangqi modules and the two-line API router registration onto a copy of the current API release. Compare the router's previous bytes before applying. Other compiled modules and the frontend release stay unchanged. Serve static files through a dedicated Nginx include; verify its complete previous configuration and retain a rollback copy. Retain and cold-start the old API against the additive migration before switching.

## Verification

API typecheck/build, real PostgreSQL-compatible PGlite migration and HTTP regression passed. Checks cover anonymous cookies, simultaneous joins, stale moves, replay, illegal moves, consent, rematch color exchange, expiry, CSRF, unknown fields, identity isolation and client/server engine parity. Existing API security and Gomoku PostgreSQL/HTTP regressions passed.

Production deployment, public readback, and browser/phone acceptance will be recorded after execution. Local checks alone are not phone acceptance.
